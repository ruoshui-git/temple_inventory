# Movement editor polish, location model redesign, loading and draft consistency

## Context
The last commit (`aca47c6`) reworked movement creation, but the result is still not intuitive.

**Visual problems**
- The preview collapse is a fat 44px "‹" button that covers the panel text (`OperationEditorView.vue:552-561`, `forms.css:726-771`). When collapsed, the panel is 48px wide inside a 44px column.
- The expand icon sits under the "操作物资" heading (`OperationLines.vue:974-983`), not on it.

**Noise**
- The 入库 picker shows a warehouse filter and a warehouse column that receiving doesn't need.
- New forms show browser-recovery blocks and technical status chips ("尚未创建原生记录 / 此浏览器未完成输入"), even when the form is pristine.

**Warehouses are modelled ad hoc**
- One leaf appears as `寺院仓库 / 实体库房 / 样例库房 / A02 样例 / 无货位`, "A02 样例", "无货位" or "借出 - O" depending on the screen.
- There are three label implementations.
- The `ti_room_default` leaf is never auto-created, and the editor exposes raw ERPNext concepts (type select, is_group, default checkbox).
- Sample rooms reuse real room names (A02 …) across 20+ warehouses.

**Loading is inconsistent**
- The ItemPicker hides its own skeleton and shows "正在加载物品…" text, plus a false "0 个匹配物品".
- About 35 other places use text-based loading.

The outcomes we want:
- a clean movement editor that only shows what each workflow needs;
- one location model with a single presenter;
- skeleton-plus-dim loading everywhere;
- drafts kept out of new forms, with clearer draft language.

Prefer a clean codebase over compatibility. There is no real data to migrate, and the reset script rebuilds the structure.

## 1. Location model (clean redesign)

**Concepts users see** (`Warehouse Type` holds the physical meaning; `is_group` stays the hierarchy fact):

| Concept | ERPNext shape | Holds stock? | Can contain |
|---|---|---|---|
| 区域 Area | group | no | Areas, Rooms |
| 房间 Room | group + one hidden **direct-storage leaf** | yes (via the direct leaf) | Shelves |
| 货位 Shelf | leaf; when subdivided, a group + direct leaf | yes | sub-Shelves (only after subdividing) |
| System | configured root, physical root, 借出, 损坏待处理 | special | n/a |

- **Rooms** are always created atomically as group + direct leaf. Users never see the direct leaf. Picking "演示室甲" as a destination means its direct leaf, and stock there displays as "演示室甲".
- **Subdividing** an empty Shelf converts it into group + direct leaf. A Shelf with references can't be subdivided, and the server rejects the attempt.

**Schema.** Replace `ti_room_default` in `fixtures/custom_field.json`. Removing it is fine.
- `ti_label` (Data): the user-facing local name, which can be long (e.g. 第2寺院).
- `ti_short_label` (Data, optional): a concise name (e.g. T2).
  - Wherever space matters, the presenter uses `short || label` for each segment: `label`, `path`, chips, filter rows, table cells and the native `warehouse_name`.
  - The full name appears in the node's own detail header, its tooltip (`title`) and its search text. Both names are searchable.
  - The warehouse page's create/rename dialog has 名称 plus an optional 简称.
- `ti_direct_storage` (Check): marks the hidden direct leaf.
- Warehouse Types: `Area`, `Room`, `Shelf`, `System`, seeded by `configuration.initialize()`.
- If ERPNext supports it, add a Property Setter so Desk link fields show `warehouse_name` (title field) instead of the docname. Codex verifies this against ERPNext source.

**Native naming.**
- `warehouse_name` = the path below the physical root, e.g. `演示区 / 演示室甲 / 演示架1`. The direct leaf gets `演示区 / 演示室甲 · 直接存放`.
- Generated by the server and regenerated for the whole subtree on rename or move.
- Unique by construction and readable in Desk. Docnames stay native keys and are never shown in the app.

**One server presenter** (`native_topology.present_locations`) returns, for every visible node:
- `label`: short and room-anchored, e.g. `演示室甲`, `演示室甲 / 演示架1`, `借出`. Duplicates get the minimal ancestor suffix.
- `local_label`: `ti_label`.
- `path`: e.g. `演示区 / 演示室甲 / 演示架1`. Roots are never printed, and direct leaves collapse into their owner.
- `kind`: `area | room | shelf | system`.
- `owner`: for a direct leaf, the room or shelf it stores for.
- `storable`: whether the node, or its direct leaf, can be a destination.

`browse.bootstrap`, `warehouses.tree`, `report_sources.ReportContext.label`, `projections.py:1279`, `catalog.scan_code` and the `configuration.py` candidates all consume it. Delete the `"无货位"` literals, the `breadcrumb` building and `_metadata`'s label logic.

**Backend API (`warehouses.py`, rewritten)**
- `tree()`
- `create_location(kind, label, parent)`: creates Area / Room (with direct leaf) / Shelf.
- `rename_location(name, label, version)`
- `move_location(name, parent, version)`
- `subdivide_shelf(name, version)`
- `set_disabled(name, disabled, version)`

The existing safety rules carry over:
- protected nodes stay protected;
- moves are blocked for referenced or hidden descendants, and cycles are rejected;
- a node can't be disabled while it holds stock;
- version checks;
- `validate_native_warehouse` keeps Desk edits consistent (a direct leaf must be a leaf under a Room or subdivided-Shelf group, and there is one per owner).

Stock paths are unchanged, because they already require explicit leaves (`native_stock._check_leaf`). The scanner resolving a Room or Shelf group auto-selects its direct leaf.

**Frontend**
- `services/contracts.ts` maps the presenter fields.
- `lib/warehouseLabel.ts` becomes thin readers (`warehouseLabel`, `warehousePath`). Delete `warehouseFullPath` and `shortRoomLabel`, and delete the label copy in `HierarchyFilter.vue:98-114`.
- **Destination selectors** list storable places: the Room shows its `label` and the Shelf shows its `label`, each with a muted `path` detail line.
- **Filters** show trees of Areas, Rooms and Shelves with `local_label`. Direct leaves are hidden. Selecting a Room selects its subtree. Chips show `label`.
- Fix the loan destination picker (`OperationEditorView.vue:387`), `BrowseFilters.vue:61-64`, `DashboardView.vue:99-103` and `ScanPanel.vue`.

**Warehouse management page (redesign).** Files: `features/warehouses/NativeWarehousesView.vue`, `useNativeWarehouses.ts`, `pages/Warehouses.vue`.
- The tree shows Area, Room and Shelf rows, each with a kind icon, `local_label` and a stock count. A Room's count includes its direct storage.
- Contextual actions:
  - on an Area: 添加区域 / 添加房间;
  - on a Room: 添加货位;
  - on a Shelf: 细分;
  - on any node: 重命名, 移动, 停用.
- The create/rename dialog asks only for **名称**. There is no type select, no is_group checkbox and no default checkbox.
- The detail header shows `label` with `path` under it, then stock and recent movements as today.
- ERPNext identifiers appear only in a collapsed "ERPNext 信息" disclosure.

**Desk edits stay safe** (assumes a knowledgeable Desk user, not a malicious one).
- `ti_label` is the source of truth. `validate` fills it from `warehouse_name` when it is empty (Desk create), stripping a matching parent prefix. It also recomputes this node's `warehouse_name`, so a Desk rename of `ti_label` or a parent change "just works". The field description says `warehouse_name` is derived.
- `on_update` cascades the regenerated `warehouse_name` to descendants (`frappe.db.set_value`, no recursion), and the existing allowlist sync still runs. Cache invalidation stays in `read_cache.warehouse_changed`.
- The presenter never throws on unexpected shapes:
  - a missing or unknown `warehouse_type` is derived structurally: group without a direct leaf → area; group with one → room/shelf container; leaf → shelf;
  - a Room group created in Desk without a direct leaf is shown in the tree with a "缺少直接存放位置 · 补建" repair action, and is not offered as a destination;
  - a deleted direct leaf degrades the same way;
  - a stray leaf directly under an Area is treated as a storable shelf.
- `validate_native_warehouse` still rejects real inconsistencies: a second direct leaf, a direct leaf that is a group, or a direct leaf under a non-container.
- Backend tests cover a Desk-style insert, rename, move and direct-leaf deletion through `frappe.get_doc(...).save()`.

**`initialize()`** creates only the root, physical root, 借出 and 损坏待处理 (types seeded). It no longer creates a default room, which removes the initializer-leaf removal hack. Configuration readiness treats "no rooms yet" as a guided empty state ("添加第一个房间"), not as an error.

- The general demo items (the `G-*` catalog) and **all** demo movements (receive, issue, transfer, loan/return, damage/repair/disposal, count, drafts) use only 演示室甲 / 演示架1 / 演示室乙, so demo names never collide with real rooms.
- Remove the A04–D03 rooms, T1, 样例库房, the duplicated "X 样例" rooms and the `rooms` entries in the catalog JSON that only served them.
- The ERPNext-initialized warehouses (All Warehouses, Stores, Work In Progress, Finished Goods, Goods In Transit) are removed. Also clear the Company and Stock Settings default-warehouse fields that point at them. The install self-check asserts that none remain. This extends the existing `sample_install.py:16-59`.

## 3. Drafts: hidden from new forms, two clearly named concepts
- **Remove the browser-candidate blocks** from new forms: the operation editor (`OperationEditorView.vue:268-285`), the count editor (`:237-251`), the item editor (`:55-74`), the warehouse editor and categories. Conflict, deleted and forbidden recovery notices remain.
- **When `?recovery=` is present,** apply automatically after `inspectRecovery` validation, with no second "检查并恢复" click. Show a toast: "已恢复上次在此浏览器暂存的内容". Keep the inspection failure and conflict paths.
- **Terminology** keeps ERPNext's model distinct from our mechanism, in plain language:
  - **草稿单据**: "已保存到系统的草稿，尚未改变库存；可在任何设备或 ERPNext 中继续". Document icon.
  - **浏览器暂存**: "内容尚不完整，无法存为草稿单据，暂时保存在此浏览器；换设备或清除浏览器数据会丢失". Device icon.
- **Drafts page** (`features/drafts/NativeRecordsView.vue`, `useNativeRecords.ts`).
  - One merged list, newest first. Each row shows:
    - a type tag (草稿单据 / 浏览器暂存);
    - the operation kind;
    - a content summary, e.g. `3 种物品 → 演示室甲`;
    - a relative time, e.g. `10 分钟前`.
  - Actions per row: 继续编辑 and 删除 / 放弃.
  - Filters for kind and type. A one-line explainer of the two types sits at the top, with details in a disclosure.
  - The full `RecoverySummary` and "复制完整恢复数据" move behind a per-row "查看详情" disclosure.
- **Entry points.** Add a "草稿" entry, with a count, to the 货物流动 browse page header. The 更多 page keeps its link.
- **Candidate filter.** `useOperationEditor.ts:410-420` / `useCountEditor.ts:409-418` no longer list candidates; their logic moves into the drafts page.

## 4. Loading: one skeleton-plus-dim mechanism everywhere
- **Shared primitives**, in `components/ui/`:
  - `DataTable`: the visible `loadingText` paragraph becomes sr-only (skeleton only); `loadingMore` gets its own flag; there is no duplicate error paragraph.
  - A new `AsyncRegion.vue` takes `loading`, `initialized`, `stale` and `error`, and exposes `skeleton` and default slots.
    - Before the first result it renders the skeleton slot.
    - On refetch it dims and inerts the content (the existing `is-refreshing` CSS) with one sr-only status.
  - A new `SkeletonBlock.vue` with `lines`, `card` and `list` variants, using the existing `.skeleton` CSS.
  - `DocumentLoadingState` stays for editors.
- **ItemPicker.**
  - Drop the `<p>正在加载物品…</p>` and the `v-show` wrapper, so the DataTable skeleton shows on first open.
  - Refetch dims the rows.
  - The toolbar summary shows nothing until the first response (no false "0 个").
  - `loadingMore` only counts "more" requests.
- **Replace every data-loading text indicator** listed by the exploration with `AsyncRegion` / `SkeletonBlock` / DataTable states:
  - `App.vue`, `ConfigurationView`, `DisplaySettingsView`, `NativeWarehousesView`;
  - `BatchDetailView`, `ProductDetailView`, `ItemEditorView`, `ActivityEditor`, `ActivitiesView`;
  - `OperationBrowseView`, `ExpiryBrowseView`, `PendingView`, `StockBrowseView`, `QuantitySummary`, `DashboardSection`;
  - `CategoriesPage`, `Attachments`, `LoanDetailView`, `RelatedLoanPreview`, `QuickExport`, `NativeRecordsView`, `CountWorkspace` (split empty from loading).
  - Also pass loading props to the DataTables that lack them: `CountEditorView`, `BatchDetailView`, `ProductDetailView`, `StockDetails`.
  - Remove the now-unused CSS and strings.
- **Keep:**
  - action and button progress text (`UiButton` 正在处理…, 正在保存…, upload %);
  - inline control states (SearchSelect 正在查找…, Scanner camera and barcode, ImageCrop).
  - The stale-after-failure warnings ("上次结果 · 尚未更新") remain, because they report errors, not loading.
