# UI/UX decisions

This document owns user-visible behavior, interaction and language. [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) owns visual geometry, tokens and shared component contracts. Update the relevant current-state rule and add one concise changelog line when a durable decision changes.

## Language and identity

- Product chrome, operation kinds, statuses, outcomes and document types use Chinese presentation labels. Preserve native enum keys, IDs, DocType names and query values for filtering, routing, grouping and writes. User-entered content and explicit ERPNext identifiers stay as entered.
- ERPNext UOM names remain native identity, link and filter keys. `UOM.ti_label` is the display label, falling back to the native name. `/stock/units` lists label, native UOM Category (单位类别), whole-number rule, status and usage. Labels, categories, whole-number rules and enabled state are editable; native names are fixed. A UOM used as any Item's stock unit or conversion cannot be disabled; the action shows the usage. Disabled units keep their labels and ranking everywhere and are hidden only from new-input unit pickers. Only unreferenced UOMs may be deleted. Labels and names cannot collide after trim/case folding. Search matches both. Barcode types are not stored; ERPNext uses them for EAN/UPC check digits, which decoding already validates.
- 库存列表 has a 截至 filter (mega filter; chip `截至：现在` by default): a past date (end of that day) or date and time, site time, never in the future. Rows then come from the ERPNext ledger at that moment (locations, batches, serials, 借出/损坏), expiry status is judged on that date, a theme-colored notice bar `正在查看 … 的历史库存` offers 回到现在, and stock-changing actions are hidden. Exports list 截至 and add it to the filename; 生成时间 stays the generation time.
- 库存列表 shows 位置 and 批次 as separate chip columns, each hideable; 效期 is hidden by default (cards keep the status badge). 管理与设置 and other 更多 groups show at most three equal-width cards per row.
- 效期 names the expiry concept and compound columns (date + status); the date itself is 到期日期 in columns, filters, sort and exports, with 剩余天数 and 到期状态.
- Hierarchy filters use `local_label` as the primary name and `full_label` as accessible title; search uses `search_text`. Warehouse cells, chips and selector options use canonical `label`; paths provide secondary context. Keep native warehouse keys in routes and writes.
- Category is optional. Hide root categories in ordinary labels/selectors. Category filters combine selected subtrees with an independent exact-match `无分类` option. Renaming updates linked Items; native permission, child and link guards control deletion.
- Environment branding comes from `temple_inventory_environment`: `development`, `sample`, `staging` or `production`. Missing config defaults to development only on `developer_mode`, otherwise production; unknown values default to production. Visible labels are 开发, 演示, 预发布. Production has no environment badge. See [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) for colors.

## Roles and permissions

- Four native roles, one per account, set in ERPNext Desk (Role Profiles 物资只读 / 物资录入员 / 物资负责人 / 物资管理员 are the presets): 只读 Inventory Viewer, 录入员 Inventory Operator, 负责人 Inventory Manager, 管理员 Inventory Administrator (the 物资管理员 profile adds System Manager, which is what allows Desk user administration). The app has no user, role or permission screens. Accounts without one of these roles see an explained no-access page; `Administrator` always gets in. Company, warehouse-root and User Permission limits apply on top of the role.
- 只读 browses, searches, exports and prints everything authorized. 录入员 adds Items, Batches, Activities and every Stock Entry operation through submit. 负责人 adds 盘点 and 期初库存, cancel and amend, deleting drafts, and managing 类别, 单位 and 活动类型. 管理员 adds Warehouse configuration, Settings, and deleting Items and Activities. Disabling an Item is an ordinary edit.
- Unavailable actions are not offered: a page shows only what the account can do, and 选择 mode appears only when at least one bulk action is available. A record the account can read but not edit opens as the normal read-only view, drafts included, and never autosaves; on 草稿 its action reads 查看 instead of 继续编辑. A direct URL to a page the account cannot use shows 无权限 inside the app with navigation intact. A permission failure, an empty result and any other error stay distinct. Exports, print, column choices, notifications and display settings are available to every role.
- Autosaved drafts are persisted documents, so 录入员 cannot delete them; they can only discard unsaved input, and 负责人 clears unwanted drafts. Whoever can edit a draft or Item can add and remove its attachments; removing one from a submitted record needs cancel permission (负责人 and above).

## Navigation, routes and browse

- Primary destinations are 首页、库存、货物流动、借用、更多. Desktop 库存 opens an accessible menu for 库存列表、效期批次、仓库、损坏待处理; it does not navigate on open. Mobile keeps the same five destinations and contextual inventory links. 更多 is a menu and holds 报表; browse pages are the reports.
- Canonical routes include `/stock/items/:code`, `/stock/expiry`, `/stock/batches/:name`, `/stock/warehouses`, `/stock/categories`, `/stock/damaged`, `/stock/units`, `/movements?view=items|records`, `/movements/new/:kind`, `/movements/:name`, `/loans?view=items|records`, `/loans/:name`, `/counts`, `/counts/new`, `/counts/:name`, `/drafts`, `/activities`, `/activities/types`, `/reports` and `/settings/setup`. Named routes own navigation/breadcrumbs. Retired routes are not-found. Native Stock Entry opens Movements; Stock Reconciliation opens Counts; unsupported DocTypes are rejected.
- Movement and Loan pages open on 明细 (`view=items`): a flat list of lines, ungrouped by default, headed "N 条明细 · M 种物品". 按物品汇总 is an ordinary grouping. 单据 (`view=records`) shows whole records with 物品种数. Line tables show image, 物品编号, 物品名称 (its own column, separate from the record number), status and both endpoints by default. Movement pages lead with per-unit 可用变化 on 明细 and 单据; 数量（按单位） is optional, and group rows, page totals and export 合计 rows sum 可用变化. Movement 单据 offers optional 流动数量 (how much stock the record touched: unsigned, neutral, a count adjustment sums its absolute differences) and optional 活动 / 借用方. 明细 groups by 物品, 类别, 流动类型, 来源位置, 去向位置, 活动 or 月份 on 货物流动 and by 物品, 类别, 借用方, 活动 or 月份 on 借用, on the page and in grouped XLSX; 物品 may only be the inner level, and a nested 物品 group lists only its parent group's lines. Lines under any other group render exactly like ungrouped 明细 lines. 库存 and 损坏待处理 also group by 位置 and 批次; 效期批次 by 批次 and 到期月份 (blank values group as 无批次 / 无到期日期). Movement summaries add per-unit 可用净变化 over submitted lines after the per-kind totals. Loan views put 未归还数量 before 借出数量. A record whose lines touch several locations on one side, including the checked locations of a count adjustment, shows the first location and "等 N 处" through the one shared many-locations component; the popover lists all of them and files join them with "；".
- 设置 → 显示 → 显示密度 offers 超紧凑, 紧凑, 均衡 (default) and 宽松, saved per account. Each step visibly changes tables, lists, cards, editors and page spacing on desktop and phone; 超紧凑 gives spreadsheet-like single-line table rows on desktop and two-line list rows on phones, while phone controls stay large enough to tap. Text size is set separately.
- Movement/Loan `view=items|records` is top-level URL state. Browse URLs omit defaults and encode only changed query fields, including nested scope. Movement, loan and count pages and the dashboard overview start on each account's 默认时间范围 (设置 → 显示, default 本月); a period equal to it is omitted from the URL but still shows a chip, because the rows are date-restricted; any other period is encoded, and removing a date chip lifts it to 全部时间. 设为默认 in a date filter saves the previewed preset as that area's account default (disabled for 自定义, whose fixed dates would not roll forward). Target-view changes apply that view’s defaults; history restores browse context. Cross-page links are sanitized to the target view contract; incompatible grouping is dropped. Invalid incoming queries show default results with a warning.
- Search stays visible. Search, applied chips, scan and filters share the persistent browse toolbar. A hierarchy sidebar is synchronized; hiding it does not clear selections. Filter panels stage date edits until Apply and use inclusive site-date bounds. `清除全部` resets search and filters when a filter chip is active; the search × clears only search; panel `清空筛选` clears panel fields only. Grouping is zero to two ordered levels from the active view contract.
- Bulk actions use a 选择 mode, not always-on checkboxes or 操作 columns: 库存, 效期批次, 损坏待处理 and both 借用 views offer 选择 at the top right on desktop and in the "…" menu on phones (which stays reachable while the phone header is stuck). Select mode shows checkboxes and a selection bar (已选择 N 项 · actions · 取消; sticky under the toolbar on desktop, above the bottom navigation on phones, where it replaces the floating action and keeps a visible 取消). Unavailable actions stay visible, disabled with a reason. In select mode the whole row or card toggles (Enter/Space too) instead of opening; card and list views have 选择当前 N 项 for loaded rows. Escape/取消 exits and clears; account changes clear; select mode and selection survive resize and return from detail; filtered-out rows drop from the selection. 库存: 入库/出库/调拨, plus 归还 when every selected Item has loaned stock (all its outstanding loan lines). 效期批次: 出库/调拨/报损; 损坏待处理: 修复归库/报废 (its table, like 库存: 图片, 物品名称, 物品编号, 损坏, 库存单位, 批次编号); 借用: 登记归还 into one Return.
- Every filter whose value restricts rows shows a chip, including page and account defaults (日期, 借用状态：未结清, 物品状态：启用, 库存状态：有库存, 活动状态, 单据状态); page-identity constraints without a control (损坏待处理, 效期 全部) do not. × lifts the restriction to its unrestricted value. 恢复默认 (panel and chip bar) restores the page defaults and is hidden when filters already match them.
- Every browse filter must change the rows of every view that shows it; merge filters with overlapping meaning. Browse fixes apply to all browse pages (盘点记录, 活动, 草稿, 仓库, 损坏待处理), which share the result summary and settings outlet.
- Tabs navigate between pages/sections; segmented controls switch views or filters within a page. `/` focuses the page search unless editing a field.
- Refresh keeps the prior snapshot/layout/scroll/selection and dims affected results. Failed refresh keeps stale results with `更新失败` and 重试. Do not show false empty/zero states before a successful response. Technical “previous result” wording is not user-facing.
- Tables, cards and hierarchy controls preserve matched-total meaning: grouped record totals count whole matching native documents once, not filtered child lines. Paginated counts describe immediate rows; expanded descendants do not add to parent totals. Empty, zero, false, external endpoints, invalid expiry and unavailable/error values remain distinct.
- Sortable table headers are the only sort control while a table is visible; cards and surfaces without sortable headers use SortControl. Movement-kind filters are multi-select OR; retain all, nonzero and selected zero-count kinds, with other zero-count kinds behind `无记录 N`. 盘点调整 and 期初库存 change stock, so movement pages always list them and 流动类型 is the only way to exclude them. Browse URLs encode differences from the target view's own defaults, so every sortable header round-trips through reload.

## Filters, dates and location scope

- Shared item scope includes 物品追踪: 全部、按批次管理、按序列号管理、记录效期、不追踪 (不追踪 excludes batch, expiry and serial Items). One 人员 filter has 任一角色、记录人、经手人、鉴证人 and permission-scoped suggestions; document names link to that filter. Loans add 借用方 and 归还结果. Inventory and Reports add 物品状态, default 启用, and 库存状态, evaluated per Item across the selected authorized locations: 有库存 (default; any quantity, including loaned/damaged only), 有可用, 无可用, 无库存, 全部. 类别 applies to item-level views only; by-record views (movement, loan and count records) hide it, switching to them clears it, and their sidebar shows 仓库 only. A filter disclosure shows its heading once; controls inside it don't repeat it. The inbox filters by notification type.
- Activity date filtering matches activity start/end ranges that overlap the selected period. Period presets are grouped into relative presets (including 本季度/上季度), calendar presets (current-year quarters and 去年), and 自定义. Fixed quarters are real period keys; summaries show resolved dates. There are no separate year/quarter shortcut rows.
- Location columns may add hidden, exportable 完整位置 (app path through the leaf, e.g. "T2 / A02 / S1") and ERPNext 库位 (native warehouse_name without the company suffix) companions, for visible locations only.
- Location hierarchy is Area → Room → Shelf. Room groups and subdivided Shelves have one hidden direct-storage leaf; trees hide direct leaves, while selecting a Room selects its subtree. Write selectors list storable leaves and display a Room’s direct leaf with the Room label. Compatible Warehouses outside the configured physical root stay hidden and are not adopted. The Warehouse manager supports contextual create, rename, move, disable, subdivide, direct-storage repair and delete; ERPNext identifiers remain secondary details. Delete is confirmed and allowed only when the location and its hidden direct leaf have no stock, ledger, record lines, User Permissions or other children; otherwise disable it. Location and unit changes refresh reference data in other open tabs, and the app refreshes stale reference data when it regains focus; write selectors sort locations by path.
- Available-stock effect defaults to authorized physical leaves. Explicit Warehouse scope covers all selected authorized leaves, including loaned/damaged leaves; transfers inside the set are neutral. Actual movement quantities remain separate. Expiry quantity is physical stock in the selected location; loaned and damaged quantities are separate. Invalid expiry is explicit; custom signed ranges are bounded and invalid values are not requested. Batch counts appear only for batch-tracked Items.

## Items, images, units and locations

- An Item’s `image` field alone identifies its primary image. Every other private Item File, including image Files, is an attachment. Replacing the primary leaves the old File as an attachment; removing it leaves the primary empty and never promotes an attachment. Never expose raw native image URLs. All image access is permission-filtered. `ItemImage` may use private 160px/640px WebP derivatives; lightboxes use the original. Derivative Files (`attached_to_field = ti_image_variant`) are not attachments.
- Item detail leads with a gallery (`Item.image` first, then image attachments; previous/next in the lightbox) beside the facts that matter: 分类 · 编号, name, 可用/借出/损坏, 条码, 单位 with 常用换算, 追踪 and 说明, all visible without disclosures; 附件 lists non-image files only; 编辑物品资料 opens the editor. Batch detail shows expiry status with remaining days; loan detail shows one status and keeps 借用人, 活动, 借出时间, 经办人, 用途 and 备注 visible.
- Serial Items on movement lines: 入库 takes typed or scanned serials, or 自动生成 N from the Item's 编号规则; outward lines pick from the serials currently in the source location; quantity always equals the serial count, in the stock unit. A typed serial that already exists is refused with the Item that owns it; scanning a serial adds it to its Item's line. Copies of 入库 drop serials; outward copies keep them.
- Serial loans keep the lent serial set: loan detail shows outstanding and settled serials, and 归还/损坏/遗失 start with the line's outstanding serials selected (remove chips to settle a subset); a settlement serial must still be outstanding on that exact loan line.
- Serial counts check each serial: the baseline is the leaf's serial set at the count time (from the ledger, so historical counts work); the editor marks book serials 在位/缺少 and takes 发现 serials by scan or typing. A serial row stays uncounted until reviewed, a matching set creates no record, a found serial recorded elsewhere is blocked with its location, and counting a leaf to zero uses ERPNext's native reconcile-all path.
- 序列号 is a hidden-by-default column wherever 批次编号 appears (stock locations, movement/loan/count lines, item detail) and shows automatically while 按序列号管理 is active, without changing the saved column choice; exports follow the visible columns. Search matches an exact serial; scanning a serial selects its Item, the serial and its current location. Stock cards and phone rows show a compact serial preview under that filter, and serial Items get an item-detail 序列号 tab (status 在库/借出/损坏/已出库, location, paging).
- 追踪方式 on an Item is 不追踪, 批次 (optionally 记录效期) or 序列号; serial and batch are exclusive, serial Items need a whole-number stock unit, and 编号规则 defaults to `<物品编号>-.####` so generated serials never collide. Tracking cannot change after submitted stock documents.
- Item images use a shared lightbox. Item identity links remain separate from image actions. In 选择 mode thumbnails are part of their card or row: tapping one selects it, and enlarge/detail actions return when selection ends. Current readable Item names/images are display metadata for native lines; otherwise use stored name, then code. Attachments preserve original bytes. Main-image editing offers crop, use-original and save-original-as-attachment. Selection is square; crop stage follows image aspect.
- Unit labels are used in frontend, exports, notifications and Desk. Seed labels only where blank, on every migrate, from a curated set for ERPNext built-ins: count units use Chinese labels (Nos→个, Unit→件, Box→箱, Pair→双, Set→套), time units Chinese (小时, 天…), measures short symbols; scientific units keep native names. Creating a unit whose name or label (trimmed, case-folded) already belongs to a unit resolves to that unit, so no Chinese twin of a built-in can exist; sample-only units 包/瓶/张 have no built-in equivalent. Multi-unit lists rank by Item usage, unknown units last. Dashboard inventory cards show three units; dashboard movement tiles show two; Activity detail kind tiles show three. Browse group totals (GroupTotals) show two values inline, every non-zero metric before a second unit of any metric, and a `+N` button (tappable on phones) lists every metric and unit. Each surface discloses remaining values. Show conversion result first (`2 箱 = 24 个（1 箱 = 12 个）`); omit conversion text for stock unit, and omit the rate when one unit was entered.
- Movement endpoints use LocationEndpoint semantics: physical locations use canonical labels; loaned/damaged endpoints are distinct; empty endpoints mean 外部 with kind-specific help. A count adjustment names checked locations, not a transfer to/from outside inventory. RecordRef names the native kind and links the related document. Mixed-value summaries label each field.
- ItemPicker keeps one row identity per Item and Warehouse. Outbound choices show available quantity; repair/disposal show damaged quantity. Inbound shows category only, omits warehouse filter/column, includes stockless Items and binds the chosen authorized destination. Count selection deduplicates Item codes while retaining full authorized Warehouse scope. Newly created Items stay pinned until the picker closes.
- 仓库 is warehouse settings only: the detail shows identity, a per-unit stock total for the node and its subtree, and 查看库存, which opens 库存 scoped to that warehouse; there is no embedded stock table. Desktop shows tree and detail side by side; on phones a node opens the full-screen detail route.
- 单位 filters by 单位类别, 整数 and 状态, groups by 单位类别 (collapsible) and sorts by column; table and phone list share the filters.

- 活动类型 are managed at 活动 → 管理活动类型 (`/activities/types`, also under 更多 → 管理与设置): create, rename, reorder, enable/disable and delete. A disabled type stays on existing activities but cannot be chosen for new ones, and its activities leave operation pickers; a type used by any activity cannot be deleted.

## Movements, documents and counts

- Dashboard quick actions are 入库、出库、借出、调拨. 更多 has 盘点调整、损坏、遗失、修复、报废 and 归还 guidance to outstanding loans. Actions reuse existing editors; clicking never creates or submits a document.
- Movement editors organize native lines into location sections: Receive, Return and Repair by target; outbound kinds and Transfer by source. Transfer rows retain per-line destination. Each native line has its own Item, batch, dates, quantity and unit; row actions move, replace, duplicate or delete a line. Required column headers use `*`; optional 生产日期 uses muted 可选. 添加物品 is the main section action; adding a location is quiet. Reason/return outcome are inline. Unit conversion returns focus to quantity. Blank Receive batch IDs are generated on save by ERPNext naming series.
- Receive and Transfer remember the account’s last selected physical leaf in Frappe user defaults; discard remembered values no longer permitted. Receive requires an explicit or remembered target before adding items. Transfer’s toolbar destination seeds new lines, but each line remains independently editable and cannot equal its source. Loan destination is server-assigned and hidden. Supporting-data creation preserves the open draft and context; a new activity is created in a stacked dialog and its title shows immediately. Activity choices come from a lightweight, debounced search. Outbound lines show read-only 现有 stock at their source location or chosen batch. Borrowers are 借用方 (a person or group) everywhere.
- Optional recorder, handler and reviewer text remains separate from the system account. Expired batches may be received; show state without blocking a valid receipt. A batch may have expiry without manufacturing date; compare only when both exist and reject manufacturing later than expiry. Within one Receive form, blank-batch rows with the same Item, 生产日期 and 到期日期 share one generated batch; changing one row's Item or dates splits only that row (a sole holder re-dates its own generated batch, a shared one gets a new batch; the server refuses to re-date a batch another row or bundle references). Typed or picked batch numbers and batches of reopened drafts are never regrouped. A row may switch from its generated batch to an existing or new batch number; the superseded generated batch is deleted when nothing references it. 复制为新草稿 and 修订 keep each row's zero-valuation allowance so donated Items without a valuation still submit.
- Count captures the complete authorized physical leaf set at one posting timestamp. The grid lists every non-zero stock row in those leaves (one set-based ledger read); 添加物品 adds zero-stock Item × leaf rows. There is no scope/method section; `?warehouse=` only presets the location filter. Like other operation forms, time defaults to 确认时的当前时间 with 指定历史时间, and the shared action bar sits at the form end (sticky on desktop, fixed on phones). Confirming re-reads 账面 on the server; rows whose 账面 changed since counting are flagged and need 确认仍按当前实点. Blocked confirmation names the actual reasons. The grid groups by 位置 (default), 物品 or none; editor, confirmation and detail show differences and 增加/减少/净差异 with signed colors, and the detail table is grouped by location. Search, location and review filters change visible rows only; paging retains entries. Blank is uncounted, zero is counted zero. Matching counts create no record. Difference reasons/notes are optional. Submitted and cancelled counts show only changed lines in a read-only table, with "另有 N 个物品核对无变化" for reviewed zero-difference rows the app keeps in its review table; drafts keep the full workspace. Count summaries, the counts list and its export separate 增加, 减少 and 净差异 per unit (净差异 is the offset net). The counts list has one value per column, includes 期初库存 and has no borrower. Count scanning locates an Item or Warehouse and never changes count quantity.
- 期初库存 (`/counts/opening/new`, from 盘点调整 and 更多, 负责人 and 管理员) declares the first quantity of an Item in a location; it is not a 盘点, so it has its own editor rather than a baseline grid. Each line takes 物品, 位置, 数量 and 估值单价, plus 批次 and 到期日期 or 序列号 for tracked Items. 期初日期 and 时间 are explicit and never in the future; 差额科目 is the company's Temporary account, chosen by the server. A blank or zero 估值单价 uses ERPNext's existing rate if there is one, otherwise the line records zero value with a visible note, as for donated goods. Typing a new 批次编号 creates that batch when the field is left, never per keystroke. Only authorized physical leaves are allowed. An Item × location is eligible only with no active ledger entry at any date and no other submitted 期初库存; another draft holding it blocks at 确认, and the message names the Item, location and record and points to 盘点调整. Other locations of the same Item stay open, so warehouses can be initialized at different times. Records keep native draft, cancel and amend rules; amending restores batches and serials. Above 100 lines 确认 runs in the background, shows 正在后台提交…, and a failure returns to the draft with the reason.
- Item Code identifies a style/type, not a physical unit. New Item code previews the locked `ITM-######` series without reservation, then allocates on save. Tracking settings may change until native submitted transactions forbid it. Stop disabling only with zero stock everywhere; delete only when nothing links to the Item. New Items are available immediately to the creating transaction.
- Browse and document headers use the same labeled native status badge. Submitted history shows submitted native documents only. A pristine new editor has no record/status chip. After edit, use plain statuses: 未保存、正在保存草稿单据…、已存为草稿单据、已暂存在此浏览器、保存失败; show conflict, deleted and forbidden states plainly. Saved document name is secondary.
- 草稿单据 is a system-saved native draft, unchanged stock, resumable on any device or in ERPNext. 浏览器暂存 is incomplete input stored only in this browser/account and may be lost with browser data. New forms do not list browser snapshots. `/drafts` combines both newest first with kind/source filters; rows summarize first Item + remaining kinds + location, show site-timezone relative time, open and continue-edit actions. Opening recovery validates/applies the snapshot; confirm with a toast and show inspection/version conflicts.
- Activity references use immutable IDs. Renames update display metadata. Enabled types populate selectors; retired linked types stay readable on unrelated edits. Notes are searchable multiline text, separate from short descriptions. Archive blocks new assignment but preserves links/settlement; references block deletion. Activity counts are submitted documents, not quantities. Activity overview shows frequent kinds with a `+N` disclosure; detail tiles link to filtered Movements/Loans instead of embedding record tables.
- Loans have one 借用状态 filter for 明细 and 单据: 未结清 (default, the 借出清单), 已结清, 全部; a non-default value shows a chip. 明细 lists matching loan lines (全部 adds their return, damage and loss lines); 单据 lists matching loan documents (全部 adds their 归还/损坏/遗失 documents). It is URL state and drives the export; 明细 quantities are signed (loan +, return −) under 借还数量 and labels are neutral (日期, 编号, 来源位置). Status changes restart open histories; closed histories load lazily. Only original submitted Loan documents show settlement status; other operations show native status. 结算记录 and 原借出 link the two both ways and export under the same labels; headers are neutral (编号, 日期).
- One 归还 may settle loans from several 借用方 and 活动. Each line keeps its original loan's 借用方 and 活动; the server derives the header (the shared value, else blank) and ignores client values on settlements. The Return editor has no 借用方 field or 活动 picker: it lists each loan as 原借出 · 借用方 · 活动, and the header shows 多个借用方 / 多个活动 when they differ. Reports, the 借用方 filter and activity counts attribute settlement lines through their original loan; a mixed Return counts once per activity it touches.

## Imports

- 物品导入 (`/imports/items`, 更多 → 工作工具, 负责人 and 管理员) runs 下载模板 / 下载物品目录 → upload → preview → 确认导入 → result. The preview writes nothing and shows each row as 新建, 更新, 无变化 or 无法导入, with summary tiles that filter, search, and before/after for updates. Commit rechecks everything against live data; if anything changed it stops at 数据已变化，请重新预览 with nothing written. Rows that cannot be imported block the import until 跳过 N 行无法导入的行 is ticked. All Items in one import are written together or not at all. The result shows generated 物品编号 and offers a report; the catalog download has the same columns, so it doubles as a code list and an update file.
- 物品编号 means update. Otherwise 导入参考号, or a fingerprint of name, category, unit and description when it is blank, identifies a row, so a retried file creates no duplicates. A matching name alone is only a warning. A blank cell keeps the existing value. Barcodes are only added, never removed; one cell may hold several, separated by ；. Unknown categories and units are rejected, never created. 记录效期 turns on batch tracking, as in the Item editor. 库存单位 and locked tracking follow the same rules as the editor.
- 期初库存导入 (`/imports/opening`, 负责人 and 管理员) takes 期初日期 and 时间 before the upload; they are never in the future and they are the time the stock is recorded. Rows give 物品编号, 位置 (label, path or ERPNext name, from the template's 位置清单), 数量, 估值单价, and 批次 or 序列号 where the Item tracks them. Items are never created here: an unknown 物品编号 is rejected, so 物品导入 comes first. The preview writes nothing and shows each row as 新增, 无变化 (the same opening already exists) or 无法导入 with the reason, using the same eligibility as the 期初库存 editor. One import becomes exactly one native 期初库存 across all its locations; it is never split. A retried import finds the same document instead of creating another. If submission fails, the draft stays for correction and the result says so. Writes to the import's locations wait while it submits, so large imports belong in a quiet time.

## Dashboard, reports and export

- Dashboard distribution sorts stocked groups by Item count and initially shows eight. Empty physical locations are a separate expandable list. Category distribution labels uncategorized stock 无分类 and omits an empty category summary. Expiry preview is limited to five batches and retains the selected expired/dated-not-expired window. Movement tiles and recent records link to detail; quantity disclosure does not steal the link. Stock-effect wording is title/screen-reader text only.
- Reports retain complete scope/matched counts, fixed view columns, distinct units/statuses, pending-until-Apply dates and account-scoped preferences. Historical Inventory is opening + incoming − outgoing + adjustment = closing; transfers retain both branches and net to zero in combined scope. No valuation or parallel ledger.
- 导出 writes the page's line table with the page's filters and visible columns in screen order, for all matching rows; the page is the preview. The dialog shows the page title, filter chips and row count, then format (XLSX / CSV / PDF), 按当前分组输出 (XLSX and PDF, when grouped) and 附带文件 (无 / 物品图片 / 图片和附件). Every export field is a browse column (export-only data such as 库位, 批次编号, 到期日期, 时间, 原借出 and 单位 are hidden by default), and a parity test keeps export fields and headers equal to browse columns. Files use the page's own column labels as headers and display labels; quantities stay numeric with an adjacent 单位 column, a mixed-unit record writes one row per unit, files end with one 合计 row per unit (movement pages total 可用变化), are named page–period–time, and XLSX adds an 导出说明 sheet listing page, filters, grouping, sort, period, time, account and row count. Grouped XLSX writes grey "label (N)" rows with numeric subtotals and unit when the group has one unit, otherwise one "小计 · 单位" row per unit, details on an expanded, collapsible outline. 附带文件 produces a ZIP: `images/<物品编号>.*` originals linked from 图片文件, `attachments/items/<物品编号>/` and `attachments/records/<编号>/`, each file once. Dashboard may choose the dataset; other pages are fixed. Canceling does not change dashboard scope. 导出 is a menu item (the “…” sheet on phones); the dialog mounts outside the menu so the sheet closing never unmounts it. 开始导出 closes the dialog and hands the job to the 后台任务 tray: a bottom-end pill (above the phone FAB and navigation) with progress that expands to each task's request time (`请求于`, date added when not today), stage, 下载, 重试 and 移除; it keeps polling across pages and reloads, and an open panel stays open when work ends. The 导出完成 notification remains the history; there is no download page. 库存列表 export grain follows its visible columns: a batch-level column (批次, 批次编号, 序列号, 效期, 到期日期, 剩余天数, 到期状态) writes item × location × batch rows, otherwise a location column (位置, 库位, 完整位置, ERPNext 库位) writes item × location rows with batches summed, otherwise one row per item.
- PDF export uses a Print Format on Inventory Export Request (版式): 物资表格 for every page, plus 盘点表 for stock data (blank 实盘/备注 columns, 盘点人/复核人/日期 lines, no totals). It prints the same rows, visible columns and grouping as XLSX with a leading #, never files. The server sizes each column to its content so only the item name takes spare width; the item name keeps one line when the page allows, with 位置/类别 and other wrappable text giving up width down to their 90th-percentile value so only their longest cells wrap, and with 纸张方向 自动 picks Letter portrait or landscape and a font step to fit; 纵向/横向 keep that orientation and only step fonts and wrapping. Margins are 6mm. Long text wraps only when needed; the title, filter line, 小计, 说明 and signature lines wrap inside the page instead of running past it. 版式 loads for every export page; if it fails, PDF cannot start. Rows are capped by Temple Inventory Settings → PDF 最多行数 (default 5,000). Standard formats ship with the app; duplicates made in Desk appear in 版式.
- Saved movement, loan and count records offer 打印 (the server renders the slip as HTML and the browser's own print dialog is the preview) and 下载 PDF (a 后台任务 tray task): a Letter portrait slip in large type (title `日期【位置】类型登记表` with 单号 on every page, #, 类别, 物品名称, 物品编号, 数量, 单位 and only the batch/expiry/serial/location columns that have values; counts show 账面/实盘/差异), then 小计, 说明 and signature lines per kind. Drafts and cancelled records carry a watermark; unsaved edits disable 打印. The slip is the DocType's Default Print Format when one is set in Desk, otherwise the shipped 物资单据 / 盘点单. Text columns wrap before the font goes below 10.5pt.
- Activity detail links kind tiles and outstanding-loan tile to Movements/Loans filtered by activity. Loan detail shows only 原存放. Read-only document lines are grouped by location, one row per line; batch splits list each batch, quantity and expiry inside that row. Group headers and 操作汇总 use stock-unit totals. Read-only aside shows aggregates only; editor aside adds line checks; review dialog folds empty optional fields into `未填写：…`.

## Notifications and scanner

- Inventory notifications use Frappe Notification Log and app-owned Notification Types; Desk bell and inventory inbox show the same events. Defaults are on except daily expiry digest, which is off. Recipients are enabled System Users with app access, excluding actor, with the event enabled, Frappe notifications enabled and native read permission. Export completion/failure notifies the requester; a result watched live is created as read. Expired export files remain listed as unavailable. Workers report stages (读取数据 / 写入文件 / 打包附件) with progress; downloads recheck permissions once and stream with byte progress. Push status distinguishes unsupported browser, insecure context, denied permission (with steps to re-allow and 重新检查), iOS outside standalone mode, permission granted without a device subscription and active subscription; 发送测试通知 pushes to the caller's own devices. A one-time, account-scoped prompt offers to enable system notifications where push can work; after permission is granted it ends on success or shows the failure once. Endpoints are stored whole and deduplicated by hash; a failed server save unsubscribes the new browser subscription, and the app re-saves a browser subscription the server lacks. Sends use a 24-hour TTL; test sends refresh each device's last result. The bell popover reloads rows when opened and when the unread count changes.
- Scanning is one workflow for camera, hardware scanner and manual entry. Browse scans share lookup behavior: a scan fills the page search, and browse search matches Item barcodes (whole or partial) as well as code and name on every item-based page; editor scans resolve Item/location/batch ambiguity before adding. Picker selection scans are idempotent. Operation picker adds one stock unit, does not submit, and undo reverses only the latest unchanged increment. Count scans never alter count values.
- Camera decoding uses the centered square visible through the square cover viewport; the aim box is guidance only. Request ideal 1920×1080 and allow browser dimensions; scale frames above 1000px down. Torch appears only when supported. Accepted camera decodes briefly flash the aim frame and vibrate where available; reduced motion removes transition. Re-arm a held code after 500ms of successful empty frames; decode errors never count as absence, and every failed frame resets the interval. Manual entry and scan-gun Enter count deliberate submissions. Image decoding occurs locally only within an open scanner surface; it never replaces a text paste or uploads the image. Failures offer crop/quarter-turn retry.

## Feedback, accessibility and responsive behavior

- Shared breakpoint is 1024px. One active surface is mounted while its controller retains state across viewport changes. Every card view and phone row list ends with 加载更多 (BrowseLoadMore) when no table owns paging. Item cards on 库存, 效期批次, 损坏待处理 and 货物流动/借用 明细 share ItemCard: framed image, category · code, name, large quantity and status badge, with page details below. A grouped 表格 hides the columns its group headers already determine (物品 → image, 名称, 编号, 类别, 单位; 位置, 批次, 类型, 借用方, 活动, 状态 likewise; 月份 hides nothing); 显示字段 marks them 分组标题已显示, and saved fields, cards, 列表 rows and exports keep them. 库存 cards also work when grouped: each group (nested groups too) shows its label, count and per-unit totals with the table's collapse state, per-group paging and selection. 效期批次, 损坏待处理 and 货物流动/借用 明细 offer cards ungrouped or grouped exactly by 物品 (other groupings stay tables); an item-group card opens its lines with 查看物品 inside. Layouts are 表格 (DataTable), 列表 (two-line rows) and 卡片 (card grid). Item pages (库存, 效期批次, 损坏待处理, 明细) offer 表格/卡片 on desktop and 列表/卡片/表格 on phones (列表 by default); 单据 lists of 货物流动/借用, 盘点记录, 草稿 and 活动 are 表格 on desktop and 列表/表格 on phones (列表 by default). On every browse page and form factor one icon-only ViewModeToggle (表格/列表/卡片) sits in the result-summary controls beside ☷ 显示字段, on the label's line when the label is short and wrapped under it otherwise; it is hidden when a page offers one layout. Neither is ever in the “…” menu. Every layout shows the page's empty wording when no rows match. A 列表 row or card whose text is cut off, or whose fields exceed the limit, ends its field line with 更多 (or +N 项); it opens a sheet listing every 显示字段 in full, with 打开, while a tap elsewhere on the row still opens the record. The choice is remembered per account, page and form factor in this browser. 显示字段 is one per-page field selection that drives every layout: the table shows the visible columns in order; cards place the image, name, category · code, hero quantity and status badge in fixed slots when those columns are visible and list the other visible columns under the quantity as the card's muted meta line of `label value` pairs (at most 8, then +N 项; chips such as 位置/批次 on a line of their own); 列表 rows show the name, hero quantity and badge on line 1 and the same pairs on line 2 (at most 6). Codes, dates, statuses and chips show without a visible label unless empty. Every item card grid is two cards per row on phones, and every item 列表 row (库存, 效期批次, 损坏待处理, 货物流动/借用 明细) shares the 库存 row: 64px thumbnail, name with badges, quantity at the end. Card fields end in … at the card edge. A whole card or row is the click target and shows the pointer; cards tint their border on hover. The unit column folds into the hero quantity; action columns stay table-only; 库存 and 效期批次 cards keep the expiry badge whatever the 效期 column choice. 草稿 on desktop stays a fixed list. Phone count lines are compact cards, 100 per page; Enter advances input. Desktop keeps table. Editors hide bottom navigation on phones.
- Browse tables, 报表 and the 盘点 editor keep their column header in view while the page scrolls, and grouped tables keep the current group row or rows under it: one per grouping level, each with its totals still aligned to their columns, replaced as the next group arrives. The stack is app navigation, toolbar, column header, group rows; on phones the search bar, column header, group rows. Once the page has more scroll room than the toolbar's height, the desktop toolbar condenses to one line (title text hidden, chips scroll sideways, the 明细/单据 switch and actions stay), as phones already do; shorter pages keep the full toolbar so nothing flickers. A table wider than its box keeps a sticky header and group rows only in browsers with single-axis scroll containers (Chromium 156+); Safari and Firefox keep that table's header in its normal place, while tables that fit their width stick everywhere. Clicking a stuck group row collapses it and leaves it at the sticky line. Keyboard focus never lands under the sticky layers. Card and phone-list group headings stick under the toolbar until their group ends. Dialogs, pickers and detail panes keep ordinary tables.
- Interactive mobile/coarse-pointer targets are at least 44px. On phone item-group lists the whole heading except the thumbnail toggles the group; item details open from 查看物品 inside it. Keep focus visible, labels/state exposed, and honor reduced motion. Desktop tables use roving row focus; Up/Down, Home/End move rows, Enter opens the row, Space toggles selection, Left/Right controls groups. Native controls remain independently reachable in DOM order. Return from detail restores originating row focus. Ctrl/⌘+Enter opens review only and never submits.
- Leave/reload/discard/delete use ConfirmDialog. Backdrop dismissal requires the press to start and end on the backdrop; a drag out of the panel never closes it. Escape/system Back closes only the top dismissible overlay; keep nondismissible layers open. Nested supporting-data dialogs stack above their parent and close in order (top first); completing one closes only it. Attachments open in an in-app viewer: images and PDFs inline, plain text framed, other files with 在新标签打开 and 下载. Attachments can be added or removed on draft and submitted records; cancelled records are read-only. Content dialogs become sheets on phones; right drawers are retired. Scanner is a dialog; ItemPicker keeps its inline scan stage.
- Form errors appear beside fields; focus the first actionable error. Server/save errors retain detail in danger callouts. Pending state belongs to the triggering action and disables siblings. Initial async loads use shape-matched skeletons; loading options do not silently change.
- Refresh dims only affected results, retains usable headings/controls and disables stale-result actions only. A failed refresh keeps results and retry. Card requests stay local; page refresh affects all result regions. Toasts report explicit outcomes (manual save, submit/cancel/amend/duplicate/delete, supporting data, file/image changes, export/copy); routine autosave/filter/scan feedback stays local. PWA updates use a persistent dismissible toast that stays until 更新 or dismissal (signing in never clears it) and appears only in a tab still running the old code: a fresh load is already current and activates the waiting worker without a prompt, and 更新 reloads even when another tab already activated the new worker.
- While the site is in maintenance mode (deploys), every page shows a branded 系统正在更新 card with an English line, a 刷新 button and a 30-second auto-refresh instead of Frappe's English “Updating” page; API calls still get JSON 503.
- Times display in site wall time to the second: `YYYY-MM-DD HH:MM:SS`, time-only `HH:MM:SS`, zero-padded, never fractions or device-local time; exports write the same. Payloads keep native precision (zero-padded, with microseconds) so sorting and the report snapshot used as the "as of" bound for balances stay exact.
- 复核并确认 opens the review at once from client-validated data; latest loan balances are checked in the background and 确认 shows 正在核对最新库存… until they finish. Current-time operations show 确认时的当前时间 and the server stamps the time on confirm. Review shows 自动生成 only for Receive lines whose Item tracks batches.
- Focus reveal is the browser's own. App code scrolls only when fixed app chrome covers the focused field and never on focusout. Anchored popups place within the visual viewport (keyboard open) and stay still while their own list scrolls.
- Confirming a draft is single-flight: the confirm button is busy from the first click, waits for an in-flight autosave, skips a save when nothing changed, and clears earlier errors on success. Server messages name Items by name and code and locations by presenter label, never native Warehouse names.
- Browser title is `<app title> | <page>`. Clickable elements show pointer affordance; other elements do not. Hover tint is limited to hover-capable pointers.
