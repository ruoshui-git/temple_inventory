# UI/UX decisions

This document owns user-visible behavior, interaction and language. [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) owns visual geometry, tokens and shared component contracts. Update the relevant current-state rule and add one concise changelog line when a durable decision changes.

## Language and identity

- Product chrome, operation kinds, statuses, outcomes and document types use Chinese presentation labels. Preserve native enum keys, IDs, DocType names and query values for filtering, routing, grouping and writes. User-entered content and explicit ERPNext identifiers stay as entered.
- ERPNext UOM names remain native identity, link and filter keys. `UOM.ti_label` is the display label, falling back to the native name. `/stock/units` lists label, native UOM Category (单位类别), whole-number rule, status and usage. Labels, categories, whole-number rules and enabled state are editable; native names are fixed. A UOM used as any Item's stock unit or conversion cannot be disabled; the action shows the usage. Disabled units keep their labels and ranking everywhere and are hidden only from new-input unit pickers. Only unreferenced UOMs may be deleted. Labels and names cannot collide after trim/case folding. Search matches both. Barcode types are not stored; ERPNext uses them for EAN/UPC check digits, which decoding already validates.
- 效期 names the expiry concept and compound columns (date + status); the date itself is 到期日期 in columns, filters, sort and exports, with 剩余天数 and 到期状态.
- Hierarchy filters use `local_label` as the primary name and `full_label` as accessible title; search uses `search_text`. Warehouse cells, chips and selector options use canonical `label`; paths provide secondary context. Keep native warehouse keys in routes and writes.
- Category is optional. Hide root categories in ordinary labels/selectors. Category filters combine selected subtrees with an independent exact-match `无分类` option. Renaming updates linked Items; native permission, child and link guards control deletion.
- Environment branding comes from `temple_inventory_environment`: `development`, `sample`, `staging` or `production`. Missing config defaults to development only on `developer_mode`, otherwise production; unknown values default to production. Visible labels are 开发, 演示, 预发布. Production has no environment badge. See [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) for colors.

## Navigation, routes and browse

- Primary destinations are 首页、库存、货物流动、借用、更多. Desktop 库存 opens an accessible menu for 库存列表、效期批次、仓库、损坏待处理; it does not navigate on open. Mobile keeps the same five destinations and contextual inventory links. 更多 is a menu and holds 报表; browse pages are the reports.
- Canonical routes include `/stock/items/:code`, `/stock/expiry`, `/stock/batches/:name`, `/stock/warehouses`, `/stock/categories`, `/stock/damaged`, `/stock/units`, `/movements?view=items|records`, `/movements/new/:kind`, `/movements/:name`, `/loans?view=items|records`, `/loans/:name`, `/counts`, `/counts/new`, `/counts/:name`, `/drafts`, `/activities`, `/reports` and `/settings/setup`. Named routes own navigation/breadcrumbs. Retired routes are not-found. Native Stock Entry opens Movements; Stock Reconciliation opens Counts; unsupported DocTypes are rejected.
- Movement and Loan pages open on 明细 (`view=items`): a flat list of lines, ungrouped by default, headed "N 条明细 · M 种物品". 按物品汇总 is an ordinary grouping. 单据 (`view=records`) shows whole records with 物品种数. Line tables show image, 物品编号, 物品名称 (its own column, separate from the record number), status and both endpoints by default. Movement pages lead with per-unit 可用变化 on 明细 and 单据; 数量（按单位） is optional, and group rows, page totals and export 合计 rows sum 可用变化. Movement summaries add per-unit 可用净变化 over submitted lines after the per-kind totals. Loan views put 未归还数量 before 借出数量. A record whose lines touch several locations on one side shows the first location and "等 N 处"; the popover lists all of them.
- Movement/Loan `view=items|records` is top-level URL state. Browse URLs omit defaults and encode only changed query fields, including nested scope. Movement, loan and count pages and the dashboard overview start on each account's 默认时间范围 (设置 → 显示, default 本月); a period equal to it is omitted from the URL and shows no chip, any other period (including 全部时间) is encoded and removing its chip returns to the default. Target-view changes apply that view’s defaults; history restores browse context. Cross-page links are sanitized to the target view contract; incompatible grouping is dropped. Invalid incoming queries show default results with a warning.
- Search stays visible. Search, applied chips, scan and filters share the persistent browse toolbar. A hierarchy sidebar is synchronized; hiding it does not clear selections. Filter panels stage date edits until Apply and use inclusive site-date bounds. `清除全部` resets search and filters when a filter chip is active; the search × clears only search; panel `清空筛选` clears panel fields only. Grouping is zero to two ordered levels from the active view contract.
- Tabs navigate between pages/sections; segmented controls switch views or filters within a page. `/` focuses the page search unless editing a field.
- Refresh keeps the prior snapshot/layout/scroll/selection and dims affected results. Failed refresh keeps stale results with `更新失败` and 重试. Do not show false empty/zero states before a successful response. Technical “previous result” wording is not user-facing.
- Tables, cards and hierarchy controls preserve matched-total meaning: grouped record totals count whole matching native documents once, not filtered child lines. Paginated counts describe immediate rows; expanded descendants do not add to parent totals. Empty, zero, false, external endpoints, invalid expiry and unavailable/error values remain distinct.
- Sortable table headers are the only sort control while a table is visible; cards and surfaces without sortable headers use SortControl. Movement-kind filters are multi-select OR; retain all, nonzero and selected zero-count kinds, with other zero-count kinds behind `无记录 N`. 盘点调整 and 期初库存 change stock, so movement pages always list them and 流动类型 is the only way to exclude them. Browse URLs encode differences from the target view's own defaults, so every sortable header round-trips through reload.

## Filters, dates and location scope

- Shared item scope includes 物品追踪: 全部、按批次管理、记录效期、不按批次管理. One 人员 filter has 任一角色、记录人、经手人、鉴证人 and permission-scoped suggestions; document names link to that filter. Loans add 借用方 and 归还结果. Inventory and Reports add 物品状态, default 启用, and 库存状态, evaluated per Item across the selected authorized locations: 有库存 (default; any quantity, including loaned/damaged only), 有可用, 无可用, 无库存, 全部. 类别 applies to item-level views only; by-record views (movement, loan and count records) hide it, switching to them clears it, and their sidebar shows 仓库 only. A filter disclosure shows its heading once; controls inside it don't repeat it. The inbox filters by notification type.
- Activity date filtering matches activity start/end ranges that overlap the selected period. Period presets are grouped into relative presets (including 本季度/上季度), calendar presets (current-year quarters and 去年), and 自定义. Fixed quarters are real period keys; summaries show resolved dates. There are no separate year/quarter shortcut rows.
- Location columns may add hidden, exportable 完整位置 (app path through the leaf, e.g. "T2 / A02 / S1") and ERPNext 库位 (native warehouse_name without the company suffix) companions, for visible locations only.
- Location hierarchy is Area → Room → Shelf. Room groups and subdivided Shelves have one hidden direct-storage leaf; trees hide direct leaves, while selecting a Room selects its subtree. Write selectors list storable leaves and display a Room’s direct leaf with the Room label. Compatible Warehouses outside the configured physical root stay hidden and are not adopted. The Warehouse manager supports contextual create, rename, move, disable, subdivide, direct-storage repair and delete; ERPNext identifiers remain secondary details. Delete is confirmed and allowed only when the location and its hidden direct leaf have no stock, ledger, record lines, User Permissions or other children; otherwise disable it. Location and unit changes refresh reference data in other open tabs, and the app refreshes stale reference data when it regains focus; write selectors sort locations by path.
- Available-stock effect defaults to authorized physical leaves. Explicit Warehouse scope covers all selected authorized leaves, including loaned/damaged leaves; transfers inside the set are neutral. Actual movement quantities remain separate. Expiry quantity is physical stock in the selected location; loaned and damaged quantities are separate. Invalid expiry is explicit; custom signed ranges are bounded and invalid values are not requested. Batch counts appear only for batch-tracked Items.

## Items, images, units and locations

- An Item’s `image` field alone identifies its primary image. Every other private Item File, including image Files, is an attachment. Replacing the primary leaves the old File as an attachment; removing it leaves the primary empty and never promotes an attachment. Never expose raw native image URLs. All image access is permission-filtered. `ItemImage` may use private 160px/640px WebP derivatives; lightboxes use the original. Derivative Files (`attached_to_field = ti_image_variant`) are not attachments.
- Item images use a shared lightbox. Item identity links remain separate from image actions. Current readable Item names/images are display metadata for native lines; otherwise use stored name, then code. Attachments preserve original bytes. Main-image editing offers crop, use-original and save-original-as-attachment. Selection is square; crop stage follows image aspect.
- Unit labels are used in frontend, exports, notifications and Desk. Seed labels only where blank, on every migrate, from a curated set for ERPNext built-ins: count units use Chinese labels (Nos→个, Unit→件, Box→箱, Pair→双, Set→套), time units Chinese (小时, 天…), measures short symbols; scientific units keep native names. Creating a unit whose name or label (trimmed, case-folded) already belongs to a unit resolves to that unit, so no Chinese twin of a built-in can exist; sample-only units 包/瓶/张 have no built-in equivalent. Multi-unit lists rank by Item usage, unknown units last. Dashboard inventory cards show three units; dashboard movement tiles and browse group summaries show two; Activity detail kind tiles show three. Each surface discloses remaining values. Show conversion result first (`2 箱 = 24 个（1 箱 = 12 个）`); omit conversion text for stock unit, and omit the rate when one unit was entered.
- Movement endpoints use LocationEndpoint semantics: physical locations use canonical labels; loaned/damaged endpoints are distinct; empty endpoints mean 外部 with kind-specific help. A count adjustment names checked locations, not a transfer to/from outside inventory. RecordRef names the native kind and links the related document. Mixed-value summaries label each field.
- ItemPicker keeps one row identity per Item and Warehouse. Outbound choices show available quantity; repair/disposal show damaged quantity. Inbound shows category only, omits warehouse filter/column, includes stockless Items and binds the chosen authorized destination. Count selection deduplicates Item codes while retaining full authorized Warehouse scope. Newly created Items stay pinned until the picker closes.

## Movements, documents and counts

- Dashboard quick actions are 入库、出库、借出、调拨. 更多 has 盘点调整、损坏、遗失、修复、报废 and 归还 guidance to outstanding loans. Actions reuse existing editors; clicking never creates or submits a document.
- Movement editors organize native lines into location sections: Receive, Return and Repair by target; outbound kinds and Transfer by source. Transfer rows retain per-line destination. Each native line has its own Item, batch, dates, quantity and unit; row actions move, replace, duplicate or delete a line. Required column headers use `*`; optional 生产日期 uses muted 可选. 添加物品 is the main section action; adding a location is quiet. Reason/return outcome are inline. Unit conversion returns focus to quantity. Blank Receive batch IDs are generated on save by ERPNext naming series.
- Receive and Transfer remember the account’s last selected physical leaf in Frappe user defaults; discard remembered values no longer permitted. Receive requires an explicit or remembered target before adding items. Transfer’s toolbar destination seeds new lines, but each line remains independently editable and cannot equal its source. Loan destination is server-assigned and hidden. Supporting-data creation preserves the open draft and context; a new activity is created in a stacked dialog and its title shows immediately. Activity choices come from a lightweight, debounced search. Outbound lines show read-only 现有 stock at their source location or chosen batch. Borrowers are 借用方 (a person or group) everywhere.
- Optional recorder, handler and reviewer text remains separate from the system account. Expired batches may be received; show state without blocking a valid receipt. A batch may have expiry without manufacturing date; compare only when both exist and reject manufacturing later than expiry.
- Count captures the complete authorized physical leaf set at one posting timestamp. Search, location and review filters change visible rows only; paging retains entries. Blank is uncounted, zero is counted zero. Matching counts create no record. Difference reasons/notes are optional. Submitted and cancelled counts show only changed lines in a read-only table, with "另有 N 个物品核对无变化" for reviewed zero-difference rows the app keeps in its review table; drafts keep the full workspace. Count summaries, the counts list and its export separate 增加, 减少 and 净差异 per unit (净差异 is the offset net). The counts list has one value per column, includes 期初库存 and has no borrower. Count scanning locates an Item or Warehouse and never changes count quantity.
- Item Code identifies a style/type, not a physical unit. New Item code previews the locked `ITM-######` series without reservation, then allocates on save. Tracking settings may change until native submitted transactions forbid it. Stop disabling only with zero stock everywhere; delete only when nothing links to the Item. New Items are available immediately to the creating transaction.
- Browse and document headers use the same labeled native status badge. Submitted history shows submitted native documents only. A pristine new editor has no record/status chip. After edit, use plain statuses: 未保存、正在保存草稿单据…、已存为草稿单据、已暂存在此浏览器、保存失败; show conflict, deleted and forbidden states plainly. Saved document name is secondary.
- 草稿单据 is a system-saved native draft, unchanged stock, resumable on any device or in ERPNext. 浏览器暂存 is incomplete input stored only in this browser/account and may be lost with browser data. New forms do not list browser snapshots. `/drafts` combines both newest first with kind/source filters; rows summarize first Item + remaining kinds + location, show site-timezone relative time, open and continue-edit actions. Opening recovery validates/applies the snapshot; confirm with a toast and show inspection/version conflicts.
- Activity references use immutable IDs. Renames update display metadata. Enabled types populate selectors; retired linked types stay readable on unrelated edits. Notes are searchable multiline text, separate from short descriptions. Archive blocks new assignment but preserves links/settlement; references block deletion. Activity counts are submitted documents, not quantities. Activity overview shows frequent kinds with a `+N` disclosure; detail tiles link to filtered Movements/Loans instead of embedding record tables.
- Loans 明细 has one 范围 section with two independent controls. 记录范围 defaults to 仅未归还借出 (the 借出清单: open loan lines only, with 借用方, 活动 and 来源位置); 借出与归还全部记录 lists every loan line plus its return, damage and loss lines. 包括已结清物品 also lists fully returned loan lines and zero-balance Items. Both are URL state and drive the export; line quantities are signed (loan +, return −) and labels are neutral (日期, 编号, 来源位置). Scope applies to grouped and ungrouped history; changed scope restarts open histories, closed histories load lazily. Only original submitted Loan documents show settlement status; other operations show native status. 单据 uses the same 记录范围: 仅未归还借出 lists open loan documents, 借出与归还全部记录 adds their 归还/损坏/遗失 documents; 结算记录 and 原借出 link the two both ways and export under the same labels, headers are neutral (编号, 日期) and only open loans offer 登记归还.

## Dashboard, reports and export

- Dashboard distribution sorts stocked groups by Item count and initially shows eight. Empty physical locations are a separate expandable list. Category distribution labels uncategorized stock 无分类 and omits an empty category summary. Expiry preview is limited to five batches and retains the selected expired/dated-not-expired window. Movement tiles and recent records link to detail; quantity disclosure does not steal the link. Stock-effect wording is title/screen-reader text only.
- Reports retain complete scope/matched counts, fixed view columns, distinct units/statuses, pending-until-Apply dates and account-scoped preferences. Historical Inventory is opening + incoming − outgoing + adjustment = closing; transfers retain both branches and net to zero in combined scope. No valuation or parallel ledger.
- 导出 writes the page's line table with the page's filters and visible columns in screen order, for all matching rows; the page is the preview. The dialog shows the page title, filter chips and row count, then format, 按当前分组输出 (XLSX only, when grouped) and 附带文件 (无 / 物品图片 / 图片和附件). Every export field is a browse column (export-only data such as 库位, 批次编号, 到期日期, 时间, 原借出 and 单位 are hidden by default), and a parity test keeps export fields and headers equal to browse columns. Files use the page's own column labels as headers and display labels; quantities stay numeric with an adjacent 单位 column, a mixed-unit record writes one row per unit, files end with one 合计 row per unit (movement pages total 可用变化), are named page–period–time, and XLSX adds an 导出说明 sheet listing page, filters, grouping, sort, period, time, account and row count. Grouped XLSX writes grey "label (N)" rows with numeric subtotals and unit when the group has one unit, otherwise one "小计 · 单位" row per unit, details on an expanded, collapsible outline. 附带文件 produces a ZIP: `images/<物品编号>.*` originals linked from 图片文件, `attachments/items/<物品编号>/` and `attachments/records/<编号>/`, each file once. Dashboard may choose the dataset; other pages are fixed. Canceling does not change dashboard scope.
- Activity detail links kind tiles and outstanding-loan tile to Movements/Loans filtered by activity. Loan detail shows only 原存放. Read-only document lines are grouped by location, one row per line; batch splits list each batch, quantity and expiry inside that row. Group headers and 操作汇总 use stock-unit totals. Read-only aside shows aggregates only; editor aside adds line checks; review dialog folds empty optional fields into `未填写：…`.

## Notifications and scanner

- Inventory notifications use Frappe Notification Log and app-owned Notification Types; Desk bell and inventory inbox show the same events. Defaults are on except daily expiry digest, which is off. Recipients are enabled System Users with app access, excluding actor, with the event enabled, Frappe notifications enabled and native read permission. Export completion/failure notifies the requester; a result watched live is created as read. Expired export files remain listed as unavailable. Workers report stages (读取数据 / 写入文件 / 打包附件) with progress; downloads recheck permissions once and stream with byte progress. Push status distinguishes unsupported browser, insecure context, denied permission (with steps to re-allow and 重新检查), iOS outside standalone mode, permission granted without a device subscription and active subscription; 发送测试通知 pushes to the caller's own devices. A one-time, account-scoped prompt offers to enable system notifications where push can work; after permission is granted it ends on success or shows the failure once. Endpoints are stored whole and deduplicated by hash; a failed server save unsubscribes the new browser subscription, and the app re-saves a browser subscription the server lacks. Sends use a 24-hour TTL; test sends refresh each device's last result. The bell popover reloads rows when opened and when the unread count changes.
- Scanning is one workflow for camera, hardware scanner and manual entry. Browse scans share lookup behavior; editor scans resolve Item/location/batch ambiguity before adding. Picker selection scans are idempotent. Operation picker adds one stock unit, does not submit, and undo reverses only the latest unchanged increment. Count scans never alter count values.
- Camera decoding uses the centered square visible through the square cover viewport; the aim box is guidance only. Request ideal 1920×1080 and allow browser dimensions; scale frames above 1000px down. Torch appears only when supported. Accepted camera decodes briefly flash the aim frame and vibrate where available; reduced motion removes transition. Re-arm a held code after 500ms of successful empty frames; decode errors never count as absence, and every failed frame resets the interval. Manual entry and scan-gun Enter count deliberate submissions. Image decoding occurs locally only within an open scanner surface; it never replaces a text paste or uploads the image. Failures offer crop/quarter-turn retry.

## Feedback, accessibility and responsive behavior

- Shared breakpoint is 1024px. One active surface is mounted while its controller retains state across viewport changes. Phone browse defaults to Stock list rows; users can switch to cards. Phone count lines are compact cards, 100 per page; Enter advances input. Desktop keeps table. Editors hide bottom navigation on phones.
- Interactive mobile/coarse-pointer targets are at least 44px. On phone item-group lists the whole heading except the thumbnail toggles the group; item details open from 查看物品 inside it. Keep focus visible, labels/state exposed, and honor reduced motion. Desktop tables use roving row focus; Up/Down, Home/End move rows, Enter opens the row, Space toggles selection, Left/Right controls groups. Native controls remain independently reachable in DOM order. Return from detail restores originating row focus. Ctrl/⌘+Enter opens review only and never submits.
- Leave/reload/discard/delete use ConfirmDialog. Backdrop dismissal requires the press to start and end on the backdrop; a drag out of the panel never closes it. Escape/system Back closes only the top dismissible overlay; keep nondismissible layers open. Nested supporting-data dialogs stack above their parent and close in order (top first); completing one closes only it. Attachments open in an in-app viewer: images and PDFs inline, plain text framed, other files with 在新标签打开 and 下载. Attachments can be added or removed on draft and submitted records; cancelled records are read-only. Content dialogs become sheets on phones; right drawers are retired. Scanner is a dialog; ItemPicker keeps its inline scan stage.
- Form errors appear beside fields; focus the first actionable error. Server/save errors retain detail in danger callouts. Pending state belongs to the triggering action and disables siblings. Initial async loads use shape-matched skeletons; loading options do not silently change.
- Refresh dims only affected results, retains usable headings/controls and disables stale-result actions only. A failed refresh keeps results and retry. Card requests stay local; page refresh affects all result regions. Toasts report explicit outcomes (manual save, submit/cancel/amend/duplicate/delete, supporting data, file/image changes, export/copy); routine autosave/filter/scan feedback stays local. PWA updates use a persistent dismissible toast.
- Browser title is `<app title> | <page>`. Clickable elements show pointer affordance; other elements do not. Hover tint is limited to hover-capable pointers.
